# 文档分工与编号

公共内容按技术主题与证据类型组织，能够脱离聊天记录独立阅读。

## 目录职责

| 目录 | 内容 | 收录标准 |
|---|---|---|
| `docs/` | 项目模块的全面解读、系统性原理说明和阅读资料 | 面向读者，术语明确、假设完整、引用可核对 |
| `notes/` | 作者的个人笔记，以及各阶段涉及的前置知识 | 按主题整理，区分原文结论、个人理解和疑问 |
| `scripts/` | 原理示例、测量与分析程序 | 输入、输出、依赖和适用边界明确 |
| `results/` | 可分享的实验产物、汇总、配置记录与分析 | 结论可追溯到环境、方法和原始证据 |
| `environment/` | 依赖与复现环境 | 仅记录对应程序实际需要或已验证的环境 |
| `tests/` | 语义、数学关系及内容边界验证 | 对应可解释的正确性要求 |

个人阅读记录和阶段前置知识进入 `notes/`；对项目模块形成可独立阅读的系统解读后，再整理到 `docs/`。具体学习安排、Agent 辅导对话和任务书保留在本地私人工作区，不混入公开说明。

## 编号与排序

`docs/` 和 `notes/` 分别以 `00、01、02…` 编号，按文档首次进入 Git 提交的先后递增，README 在各目录内使用相同顺序。后续修改不改变原编号；同一提交纳入多份文档时，按该批确定的顺序编号。

编号表示收录顺序，标题表示内容主题。新增文档在实际涉及并整理完成后编号，不预建空的专题目录或提前占用编号。

## 公开文本的写作标准

- 直接说明问题、机制、证据与局限，不依赖作者与 Agent 的对话背景。
- 不收录个人基础评估、辅导对话、日程、进度跟踪、任务分配或待讨论的项目路线。
- 引用文献保留书目与版本信息；实验保留计时定义、配置和 provenance，避免丢失技术证据。
- 不把教学推导写成实测，也不把候选机制写成已实现成果。
- 公共文件只链接可发布内容，不能依赖 Git 忽略的本地文件。

## 本地工作区边界

个人辅导和未整理材料存放在根目录 `private/`，原始大文件与临时产物存放在 `.local/`；两者由 `.gitignore` 整目录排除。本机 Agent 工作约定也不纳入版本控制。

需要共享的解释应从私人材料中独立整理成文，清除个人背景、安排、内部路径与未核实结论，再进入对应公共目录。
