# 项目说明

本仓库记录围绕 **KV Cache 分层卸载、外部缓存复用与驱逐策略** 的系统学习与实机验证过程。项目在单张 Tesla V100 服务器上基于源码构建的 `1Cat-vLLM` 与 `Mooncake Store` 开展真实推理实验，同时配套 CPU 机制验证程序与公开轨迹模拟实验，所有公开结论均保留可核对的脚本、环境配置与实测数据。

---

## 核心研究问题

在大语言模型在线推理中，GPU 显存容量有限，长上下文与高并发很快会触发 GPU 前缀缓存淘汰。把淘汰的 KV Cache 保留在容量更大的主机 DRAM（乃至 SSD）中，能够避免前缀彻底丢失，但也引入了目录查找、跨进程/跨介质数据搬运、显存块分配与异步同步等额外开销。

本项目围绕两个紧密关联的系统问题展开：

1. **单次命中的时间账（任务 A，实机测量）**：当一段前缀已从 GPU 显存中自然淘汰、但仍保留在主机 DRAM（Mooncake Store）时，从主存读回前缀 KV 并仅计算新后缀，与直接关闭外部缓存由 GPU 重新 Prefill 相比，首 Token 延迟（TTFT）随前缀长度如何变化？省下的计算能否抵消查找与搬运代价？
2. **缓存池的命中账（任务 B，轨迹模拟）**：在真实对话与工具调用请求轨迹下，增大 KV 缓存池容量时，连续前缀 token 命中率在什么区间开始趋缓？相同容量下 FIFO、LRU 与改进驱逐策略的表现差异来自哪里？

| **后续扩展方向** | SSD 三级分层回读、活跃长序列显存溢出、预取与计算/I/O 重叠、跨节点 PD 分离 | 在 A/B 实测基础上按硬件条件推进 | ⏳ 规划中 |

## 仓库目录结构

```text
.
├── docs/          # 面向读者的项目总览文档（项目说明、项目认识、服务器目录说明）
├── notes/         # 分主题技术笔记（Transformer、KV Cache、vLLM、Mooncake、真实部署与任务 A）
├── scripts/       # 可运行程序（CPU 机制示例、任务 A 服务端编排/流式压测/诊断/汇总脚本）
├── results/       # 按阶段整理的实验报告、汇总指标、校验记录与图表
├── environment/   # CPU、ECS 与实验室 V100 环境的版本与参数快照
├── CONTRIBUTING.md
├── LICENSE
└── README.md
```

- **大文件边界**：模型权重（约 3 GiB）、编译工具链、原始完整服务日志与二进制诊断转储保存在实验服务器工作区，不纳入 Git。本地仓库与服务器目录的对应方式见 [服务器目录说明](02-服务器目录说明.md)。
- **结果收录原则**：`results/` 收录能直接回答实验问题的分析报告、汇总表、校验结论和图表；运行环境与软件版本统一记录在 `environment/`。

## 软件栈与复现入口

### 1. 基础机制检查（本地 CPU / Linux 环境）

按 [cpu-info.json](../environment/cpu-info.json) 与 [cpu-requirements.txt](../environment/cpu-requirements.txt) 准备 Python 环境后，可在仓库根目录运行：

```bash
python scripts/week1_transformer_demo.py --mode attention
python scripts/week1_kv_cache_demo.py --mode equivalence
python scripts/week1_paged_kv_demo.py
```

双进程 Mooncake Transfer Engine TCP 传输示例环境见 [mooncake-linux-info.json](../environment/mooncake-linux-info.json)，运行脚本为 [week1_mooncake_transfer_demo.py](../scripts/week1_mooncake_transfer_demo.py)。

### 2. 任务 A 实机基准（完整复现示例）

完整硬件与软件版本见 [task-a-info.json](../environment/task-a-info.json)（`Tesla V100S-PCIE-32GB`、`1Cat-vLLM v1.5.3`、`Mooncake 0.3.14`、`Qwen2.5-1.5B-Instruct` FP16）。在已准备好的单卡 V100 服务器上，可直接按以下完整流程运行两批次（36 对）已验收默认配置并生成汇总与曲线：

```bash
# 1. 指定环境激活脚本、本地模型权重目录和本次新建输出根目录
export TASK_A_ENV="$HOME/kv-cache-lab/.local/deployment/env.sh"
export TASK_A_MODEL="/data/interns/<account>/kv-cache/models/Qwen2.5-1.5B-Instruct"
export OUT="/data/interns/<account>/kv-cache/results/task-a/repro-01"

COMMON="--lengths 64,128,256,512,1024,1536 --repetitions 3 --warmups 1"

# 2. 批次 1（seed=53）：先重算，后回读
bash scripts/task_a_run.sh recompute "$OUT/compute-53" $COMMON --seed 53
bash scripts/task_a_run.sh store     "$OUT/read-53"    $COMMON --seed 53

# 3. 批次 2（seed=73）：交换顺序，先回读，后重算
bash scripts/task_a_run.sh store     "$OUT/read-73"    $COMMON --seed 73
bash scripts/task_a_run.sh recompute "$OUT/compute-73" $COMMON --seed 73

# 4. 配对审计、统计汇总并绘制 TTFT 曲线
source "$TASK_A_ENV"
python scripts/task_a_report.py \
  --pair "$OUT/compute-53" "$OUT/read-53" \
  --pair "$OUT/compute-73" "$OUT/read-73" \
  --out  "$OUT/summary" --plot
```

> **复现说明**：
> - 重新运行 `task_a_report.py` 需要完整的原始运行目录（包含服务端 `serve.log` 以校验每条回访的 DRAM tier 日志，以及 `status.json`、`run.json`、`measurements.jsonl`）。
> - 如果只需要重新绘制或核对公开曲线与统计表，可以直接读取仓库已发布的 [summary.csv](../results/week2-3/task-a/summary.csv) 和 [samples.csv](../results/week2-3/task-a/samples.csv)，无需重新在 GPU 上执行推理。
