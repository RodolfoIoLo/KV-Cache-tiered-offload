# 服务器目录说明

公开仓库保存代码、文档、环境快照与面向读者的实验报告；实验室 V100 服务器保存源码构建产物、模型权重、运行缓存以及每次实机实验的完整原始日志。本文说明实验服务器的工作区布局，以及它与本仓库各目录的对应关系。

---

## 硬件与双根目录划分

实验在实验室单卡 V100 节点上执行（`Tesla V100S-PCIE-32GB`、Ubuntu 20.04、`glibc 2.31`、约 504 GiB 主机内存）。为避免大文件撑满主目录，服务器采用两个独立根目录，由环境脚本 `~/kv-cache-lab/.local/deployment/env.sh` 统一导出：

| 环境变量 | 路径约定 | 存放内容 |
|---|---|---|
| `LAB` | `$HOME/kv-cache-lab` | 虚拟环境、1Cat-vLLM 源码、项目私有工具链、部署与实验脚本 |
| `DATA` | `/data/interns/<account>/kv-cache` | 大型模型权重、下载/编译缓存、实机实验原始产出 |

## 4. 单次实机运行目录里的文件怎么看？

每次调用 `bash scripts/task_a_run.sh <mode> <dir> ...` 都会在 `<dir>` 内生成一套自洽的审计文件：

| 文件 | 含义与核对要点 |
|---|---|
| `status.json` | 记录 `client_or_startup_exit` 与 `cleanup_exit`，两者均为 `0` 才代表本轮实验与进程清理完全成功 |
| `run.json` | 记录本轮模型路径、精度、物理块数（`160`）、`max_num_batched_tokens`、DRAM 池大小及客户端参数 |
| `gpu-before.csv` | 启动前 `nvidia-smi` 快照，用于确认实验在独占空闲 V100 上运行（本次所有正式运行均为 `32501 MiB free`） |
| `measurements.jsonl` | 首行为配置、末行为完成标记，中间逐条记录每个 `build`/`pressure`/`revisit` 的流式 TTFT、`/metrics` 增量与输出 token IDs |
| `serve.log` | vLLM 服务端日志，可核对 `GPU KV cache size: 2,560 tokens`、`MC_FORCE_TCP`、每条回访的 `Mooncake load tier summary` 与退出时的 `FLASH_ATTN_V100 fallback summary` |
| `master.log` / `owner.log` | 仅 `store` 组存在，记录 Mooncake Master 与 Owner 的 TCP 协议配置、DRAM 段注册与运行状态 |
| `diagnostics/` | 仅开启 `TASK_A_DIAGNOSTICS=1` 的非计时诊断运行存在，包含 `worker-*.jsonl`、GPU KV 二进制快照 `.bin` 与全词表 logits `.pt` |
